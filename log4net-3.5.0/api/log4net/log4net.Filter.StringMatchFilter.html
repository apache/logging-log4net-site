Properties

AcceptOnMatch

Accept when matching StringToMatch or RegexToMatch

public bool AcceptOnMatch { get; set; }

Property Value

bool

Remarks

The AcceptOnMatch property is a flag that determines the behavior when a matching Level is found. If the flag is set to true then the filter will Accept the logging event, otherwise it will Neutral the event.

The default is true i.e. to Accept the event.

MatchTimeoutMillis

Gets or sets the time, in milliseconds, that matching RegexToMatch against a single event may take before the match is abandoned.

public int MatchTimeoutMillis { get; set; }

Property Value

int

A positive number of milliseconds, or 0 to let a match run for as long as it takes.

Remarks

A regular expression that backtracks can take a very long time on some inputs. The pattern is matched while the appender lock is held, so an unbounded match would stall everything logging through the appender, and matching is therefore given a deadline. TimeoutDecision decides an event whose match is abandoned.

The pattern comes from configuration and is trusted, but the content it is matched against is not, and the content decides whether the deadline is reached. This is therefore the bound on how long one crafted event can hold the appender lock.

The default value is 50. A legitimate match over an event runs in a fraction of that; raise it if a pattern genuinely needs longer. Setting the value to 0 restores unbounded matching and is not recommended. Changing it takes effect when ActivateOptions() is called.

Exceptions

ArgumentOutOfRangeException

The value specified is negative.

Remarks

The regular expression pattern that will be matched against the rendered message. If the message matches this pattern then the filter will match. If a match is found then the result depends on the value of AcceptOnMatch.

One of StringToMatch or RegexToMatch must be specified.

TimeoutDecision

Gets or sets the decision for an event whose match was abandoned because it reached MatchTimeoutMillis.

public FilterDecision TimeoutDecision { get; set; }

Property Value

FilterDecision

Remarks

An abandoned match is not a non-match: the content being matched decides whether the deadline is reached, so treating it as "did not match" lets content choose its own outcome. In an AcceptOnMatch allowlist followed by a deny-all, that means content can suppress its own record.

The default is Neutral, which leaves the rest of the chain to decide. Set Accept to make an allowlist fail towards logging, or Deny in a deny-on-match chain. No one direction is right for every chain, which is why this is configured rather than chosen here.

public override FilterDecision Decide(LoggingEvent loggingEvent)

Parameters

the event being logged

Returns

FilterDecision

see remarks

Remarks

The rendered message is matched against the StringToMatch. If the StringToMatch occurs as a substring within the message then a match will have occurred. If no match occurs this function will return Neutral allowing other filters to check the event. If a match occurs then the value of AcceptOnMatch is checked. If it is true then Accept is returned otherwise Deny is returned.
